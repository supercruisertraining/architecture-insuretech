В текущей реализации, когда запрос отправляется в сервис `ins-product-aggregator`, 
который в свою очередь в синхронном режиме опрашивает все страховые компании, 
при росте нагрузки возникнут серьезные проблемы с производительностью. 

При росте количества страховых компаний и количества пользователей запросы будут выполнятся все дольше и дольше, что
приведет к дискомфорту для пользователей.

Вместо этого я бы использовал асинхронный способ взаимодействия между сервисами `core-app`, `ins-comp-settlement` и сервисом
`ins-product-aggregator`. При отправке запроса в сервис `ins-product-aggregator` ответ будет возвращаться сразу же. В ответе
будет отдан UUID запроса, по которому потом можно будет получить результат. 

Сформированный запрос с назначенным UUID будет отправлен в очередь на обработку, после чего результат будет возврашен
через очередь, после чего отправлен по websocket в web-приложение пользователя.
